# validator-rs — a Rust port of the X-chain context-free block validator (NOT money)

**Evidence: NEW-EXP. Not money.** `bench.py` showed the node's dominant cost is signature
verification (already handled by the [libsecp256k1 fast path](../netnode/fastverify.py)); a full
native node is only worth it at extreme scale. This is the honest **first slice** of that native
node: a **dependency-free Rust** port of the block validator's *context-free* checks — the part that
needs only the block bytes.

## What it does

Mirrors [`netnode/fullnode.py`](../netnode/fullnode.py) (the context-free validation half) plus the
structured parser and value‑rule primitives the stateful validator builds on:

- **SHA-256 / double-SHA-256** — implemented in-crate (FIPS 180-4), zero dependencies;
- **block hash** and **merkle root** recomputation;
- **structure** — ≥1 transaction, the first is a coinbase, no other is;
- **proof-of-work** — the 256-bit target from compact `nBits`, header-hash ≤ target;
- **structured transactions** — `parse_tx` / `parse_block_txs` (inputs, outputs, scripts, txids);
- **value-rule primitives** — `is_coinbase`, `sum_outputs`, and the chain's `check_coinbase_value`
  (NOV08 `==` / JAN09 `<=`).

What is **not** here: the stateful UTXO connect (double-spends, no-inflation, coinbase maturity) and
**script / ECDSA verification** — those need the UTXO set and a real secp256k1 backend + a script
interpreter, a genuinely separate effort. They stay in the Python `ChainState`; this ports the parts
that are pure byte/integer logic and fully checkable against the Python node.

```bash
cargo run --bin obl-validate -- <HEX_BLOCK>     # or pipe hex on stdin
cargo test                                       # self-verifies (see below)
```

## How it's verified

`cargo test` cross-checks the Rust against the **verified Python node**: `tests/golden.rs` embeds
golden vectors (block hex + expected block hash / merkle root / PoW / tx count) generated by
`netnode/bench.py`'s chain builder, plus the standard SHA-256 `"abc"` and empty-string vectors and a
tamper-rejection case; `tests/txparse.rs` checks the structured parser (txids, inputs, output sums)
against the Python parser and the coinbase-value rule for both chains. If the Rust computed any of
these differently, `cargo test` would fail.

**Verified:** compiled and tested with **rustc 1.97.1** (`x86_64-pc-windows-gnu`) — **6 tests pass**,
and `obl-validate` on a golden block reproduces the Python's block hash. The one novel piece (the
256-bit compact-target decode + PoW comparison) was additionally cross-checked against the Python
reference across easy / hard / edge `nBits`.

## Provenance

The consensus meaning is the lab's (faithful to v0.1); this is a **NEW-EXP** re-implementation in a
second language, useful precisely because an independent port that agrees byte-for-byte is extra
evidence the byte formats + hashing are pinned down. A tool, never authority
(`../../../common/AUTHORITY.md`). **Not money.**
